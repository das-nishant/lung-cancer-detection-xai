## ABSTRACT

Lung cancer is a leading contributor to global oncology-related mortality. While low-dose Computed Tomography (LDCT) enables early detection of pulmonary nodules, high scan volumes impose significant visual fatigue on clinical radiologists. Deep Learning (DL) architectures achieve diagnostic classification accuracy, but standard convolutional neural networks (CNNs) operate as uninterpretable "black boxes," delivering diagnostic predictions without spatial or visual justifications.

This project presents **PulmoXAI**, an Explainable AI (XAI) clinical decision-support web system engineered to classify axial thoracic CT scans into three diagnostic categories: **Normal**, **Benign Nodule**, and **Malignant Lesion**. The classification backbone utilizes a deep **ResNet-50** architecture with a custom bottleneck dense head initialized via Kaiming Normal initialization. 

To resolve the interpretability challenge, PulmoXAI integrates a custom **Gradient-weighted Class Activation Mapping (Grad-CAM)** engine connected to the final convolutional residual block (`resnet.layer4[-1]`). The engine extracts neuron activation weights through global average pooling of backward gradients and applies a Rectified Linear Unit (ReLU) to isolate positive diagnostic features. It features automatic hook deregistration to eliminate memory leaks during inference and an automated background segmentation mask ($I_{\text{gray}} \ge 25$) that suppresses false-positive activations across non-anatomical bed and air space.

The backend is built as an asynchronous microservice using **FastAPI** and **PyTorch**, backed by a thread-safe **SQLite3** diagnostic logger. The frontend client is built with **React 19**, **Vite**, and **Tailwind CSS v4**, featuring an interactive DICOM viewport with an adjustable split-slider using CSS `clip-path`, dual side-by-side view, pure thermal JET colormap rendering, window-level inversion, and printable clinical diagnostic PDF reports with automated radiologist impression notes. Evaluated across standard benchmark distributions, PulmoXAI demonstrates sub-second inference latency ($\approx 0.42\,\text{s}$), clear lesion localization, and a reliable software architecture for clinical decision support.

# CHAPTER 1: INTRODUCTION

## 1.1 Background & Clinical Context
Primary pulmonary neoplasms (lung cancers) represent the most frequent cause of cancer-related mortality on a global scale [1]. The clinical pathology is broadly divided into Non-Small Cell Lung Carcinoma (NSCLC) and Small Cell Lung Carcinoma (SCLC) [2]. Clinical outcomes depend heavily on the stage of the malignancy at first presentation; patients diagnosed with localized Stage-I pulmonary nodules demonstrate a five-year survival rate exceeding 60%, whereas metastatic Stage-IV diagnoses yield a survival rate below 8% [1, 2].

Thoracic Computed Tomography (CT) serves as the primary diagnostic imaging modality for lung cancer screening. A standard high-resolution CT session generates hundreds of cross-sectional axial slices. Clinical diagnostic radiologists must review each slice to differentiate between normal anatomical parenchymal patterns, benign non-calcified inflammatory granulomas, and early-stage malignant spiculated soft tissue lesions.

## 1.2 Motivation
With the widespread adoption of Low-Dose CT (LDCT) screening initiatives, hospital radiology departments face growing workloads. Reviewing high-dimensional multi-slice studies under tight time constraints introduces diagnostic fatigue, which can contribute to false negatives (missed early-stage malignant nodules) or false positives (unnecessary invasive needle biopsies for benign inflammatory lesions) [3].

Deep Learning systems based on Convolutional Neural Networks (CNNs) have shown high sensitivity in thoracic image analysis. However, their clinical adoption remains limited due to the **"Black Box" dilemma**: conventional networks output a scalar probability vector (e.g., `Malignant: 96.4%`) without explaining the morphological basis or anatomical location of the prediction. Clinicians cannot ethically or legally base high-risk interventions on an unverified algorithmic score. Providing pixel-level visual explanations alongside quantitative metrics is essential for establishing clinical trust.

## 1.3 Problem Statement
To design, implement, and validate an integrated Explainable Deep Learning clinical decision-support system (**PulmoXAI**) that:
1. Classifies axial thoracic CT scan slices into three distinct clinical categories: **Normal**, **Benign**, and **Malignant**.
2. Produces real-time, pixel-registered visual explanations using **Grad-CAM** on the final residual convolutional layer without modifying the core model architecture.
3. Automatically isolates bodily tissue to prevent false-positive heatmaps across background air and imaging hardware.
4. Provides quantitative Region of Interest (ROI) metrics (peak activation coordinates, high-activation area percentage, peak intensity) through an interactive web-based DICOM viewport and exportable clinical diagnostic reports.

## 1.4 Objectives of the Project
* **Objective 1 (Deep Architecture Formulation):** Adapt and fine-tune a 50-layer deep Residual Neural Network (ResNet-50) using custom bottleneck dense layers and Kaiming Normal initialization for 3-class pulmonary classification.
* **Objective 2 (Explainability Engineering):** Implement a PyTorch forward-and-backward hook Grad-CAM engine with automatic hook removal to ensure thread-safe, leak-free visual heatmap generation.
* **Objective 3 (Clinical Image Processing):** Develop an automated thoracic cavity mask to eliminate non-anatomical background artifacts and composite thermal JET colormaps directly onto native CT grayscale distributions.
* **Objective 4 (System Integration):** Build a responsive, microservice-driven architecture using FastAPI (Python) and React 19 (Vite), featuring interactive split-screen slide comparisons, window inversion, audit logging in SQLite, and printable clinical diagnostic reports.

## 1.5 Scope and Constraints
* **Clinical Imaging Scope:** The system analyzes 2D axial thoracic CT slices in standard cross-platform raster formats (PNG, JPEG) derived from DICOM datasets.
* **Computational Scope:** The system is engineered to run on both commodity CPU instances and GPU accelerators, ensuring accessibility in diverse institutional settings.
* **Clinical Boundary:** PulmoXAI is designed as an assistive, decision-support tool. It is not an autonomous diagnostic agent and remains subject to the clinical judgment of certified medical radiologists.

# CHAPTER 2: LITERATURE SURVEY & THEORETICAL FRAMEWORK

## 2.1 Computer-Aided Diagnosis (CAD) in Thoracic Imaging
Early computer-aided diagnosis systems relied on classical computer vision techniques, such as watershed transforms, active contour models, and manual feature extraction (e.g., Haralick texture features, gray-level co-occurrence matrices, and geometric circularity metrics) [3]. These methods were sensitive to variations in slice thickness, scanner calibration, and reconstruction artifacts, often yielding high false-positive rates when evaluating non-solid ground-glass opacities (GGO).

The transition to Deep Convolutional Neural Networks (CNNs) bypassed manual feature engineering by learning hierarchical representations directly from raw pixel arrays [4]. Early layers capture basic edge orientations and gradients, intermediate layers identify tissue textures, and deep convolutional layers capture complex morphological structures, including spiculated nodular margins and architectural distortions characteristic of malignancy [4].

## 2.2 Deep Residual Learning and Convolutional Networks
As convolutional networks grow deeper, they often encounter the degradation problem: as network depth increases, accuracy saturates and then rapidly degrades due to vanishing or exploding gradients. He et al. [5] addressed this issue by introducing Deep Residual Learning (ResNet). 

Instead of training stacked layers to directly fit an underlying mapping $\mathcal{H}(x)$, the layers are formulated to optimize a residual mapping:
$$\mathcal{F}(x) = \mathcal{H}(x) - x \implies \mathcal{H}(x) = \mathcal{F}(x) + x$$
This identity shortcut connection allows gradients to flow directly back through the computational graph during backpropagation:
$$\frac{\partial \mathcal{E}}{\partial x} = \frac{\partial \mathcal{E}}{\partial \mathcal{H}} \left( \frac{\partial \mathcal{F}}{\partial x} + 1 \right)$$
Even if the gradient through the weight layers $\frac{\partial \mathcal{F}}{\partial x}$ approaches zero, the identity term preserves gradient flow, preventing vanishing gradients across architectures with 50 or more layers [5].

## 2.3 Evolution of Explainability in Medical AI
Explainable AI (XAI) techniques in computer vision aim to identify the input regions that most strongly influence a network's diagnostic decisions:
1. **Saliency Maps & Backpropagation Derivatives:** Simonyan et al. [6] calculated the gradient of the output class with respect to the input image pixels:
   $$G = \left| \frac{\partial y^c}{\partial I} \right|$$
   While simple, raw pixel saliency maps often contain high-frequency noise and do not consistently identify specific class-discriminative regions.
2. **Class Activation Mapping (CAM):** Zhou et al. [7] removed all dense layers and introduced a Global Average Pooling (GAP) layer immediately before the final softmax classifier. While effective, CAM requires altering the model architecture and retraining, making it unsuitable for pre-trained networks.
3. **Gradient-Weighted Class Activation Mapping (Grad-CAM):** Selvaraju et al. [8] developed a generalized, architecture-agnostic approach. Grad-CAM calculates the gradient of the target class score with respect to the feature activation maps of the final convolutional layer. By capturing both spatial relationships and semantic context, Grad-CAM produces localized heatmaps without requiring structural modifications to the model.

## 2.5 Identified Research Gaps
1. **Absence of Unified Clinical Tooling:** Most XAI research remains confined to offline Python scripts or Jupyter Notebooks, lacking interactive tools for clinical radiologists.
2. **Background Gradient Bleed:** Standard Grad-CAM implementations often highlight background air or scanner hardware due to receptive field bleed, undermining diagnostic trust.
3. **Lack of Quantitative Metrics:** Visual heatmaps are typically presented without localized quantitative biomarkers (such as peak activation coordinates or active area percentages).
4. **Memory Leaks in Inference Microservices:** Persistently registering backward hooks without cleanup in high-throughput servers can cause memory leaks, leading to server crashes during continuous use.

## 3.3 Functional Requirements
* **FR-1 (Multi-Format Scan Ingestion):** The system must accept axial thoracic CT scans in standard raster image formats (PNG, JPEG) up to 15 MB, as well as preset benchmark cases.
* **FR-2 (3-Class Inference Execution):** The system must compute confidence scores and assign scans to one of three classes: Normal, Benign Nodule, or Malignant Lesion.
* **FR-3 (Visual Explainability Generation):** The system must compute Grad-CAM heatmaps for the target diagnostic class and composite them over the original CT scan using a thermal JET colormap.
* **FR-4 (Thoracic Background Masking):** The system must segment non-body regions and prevent heatmap artifacts from appearing over background air ($I_{\text{gray}} < 25$).
* **FR-5 (Interactive Visualization):** The client interface must provide an interactive split-slider, side-by-side view, pure heatmap view, zoom controls ($1.0\times - 2.5\times$), and film inversion.
* **FR-6 (Audit Logging & History):** All diagnostic runs must be saved to a persistent database and be accessible through search, inspection, and deletion tools.
* **FR-7 (Clinical Report Generation):** The system must generate a formatted, printable clinical diagnostic PDF report containing scan metadata, model probabilities, ROI metrics, and radiologist impression notes.

## 3.4 Non-Functional Requirements
* **NFR-1 (Inference Latency):** End-to-end inference and Grad-CAM generation must complete in under 1.5 seconds on standard CPU hardware.
* **NFR-2 (Memory Safety):** Backward gradient hooks must be deregistered after every request to maintain stable memory usage over long uptimes.
* **NFR-3 (Usability & Accessibility):** The user interface must support responsive desktop layouts with clear visual contrast and intuitive medical controls.
* **NFR-4 (Modularity & Maintainability):** The backend and frontend must operate as decoupled services using clean REST API contracts to simplify future development.

## 3.5 Feasibility Analysis
* **Technical Feasibility:** The system combines established deep learning frameworks (PyTorch) with performant web technologies (FastAPI, React 19). The architecture is well-suited for deployment on standard institutional infrastructure.
* **Operational Feasibility:** The interface uses familiar radiologic design patterns (e.g., bone window inversion, split comparison sliders), making it straightforward for clinicians to use without specialized technical training.
* **Economic Feasibility:** Built entirely on open-source frameworks without commercial licensing dependencies, PulmoXAI offers a cost-effective solution for research, clinical, and educational environments.

## 5.1 Image Preprocessing & Standardization Pipeline
Input CT scans can vary in spatial resolution, dynamic range, and color encoding. The preprocessing pipeline standardizes images to ensure consistent inference:

```
[Raw Input Image: PNG/JPG/DICOM]
               │
               ▼
[Pillow Ingestion & RGB Conversion]
• Validates format integrity
• Converts single-channel/RGBA inputs to 3-channel RGB: (H × W × 3)
               │
               ▼
[Spatial Resizing]
• Bilinear interpolation to standard dimension: (224 × 224 × 3)
• Generates standardized display image: img_np_224
               │
               ▼
[Tensor Conversion & Scaling]
• Converts to torch.FloatTensor in range [0.0, 1.0]
               │
               ▼
[ImageNet Z-Score Standardization]
• Channel-wise mean subtraction and standard deviation scaling:
  Tensor = (Pixel - μ) / σ
  where μ = [0.485, 0.456, 0.406], σ = [0.229, 0.224, 0.225]
               │
               ▼
[Batch Dimension Expansion]
• Final output tensor shape: (1, 3, 224, 224)
```

## 5.2 Deep Feature Extractor & Classification Architecture
The classification engine uses a deep **ResNet-50** residual convolutional backbone initialized with pre-trained ImageNet weights, coupled with a custom fully connected head:

```python
# Model Architecture Formulation (backend/app/ai/model.py)
class LungCancerClassifier(nn.Module):
    def __init__(self, num_classes=3):
        super(LungCancerClassifier, self).__init__()
        # Load pre-trained ResNet-50 backbone
        weights = models.ResNet50_Weights.DEFAULT
        self.resnet = models.resnet50(weights=weights)
        
        # Replace final fully connected layer with custom bottleneck head
        in_features = self.resnet.fc.in_features  # 2048 dimensions
        self.resnet.fc = nn.Sequential(
            nn.Dropout(0.3),
            nn.Linear(in_features, 512),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(512, num_classes)
        )
        self._init_custom_weights()

    def _init_custom_weights(self):
        torch.manual_seed(42)
        for m in self.resnet.fc.modules():
            if isinstance(m, nn.Linear):
                nn.init.kaiming_normal_(m.weight, mode='fan_out', nonlinearity='relu')
                if m.bias is not None:
                    nn.init.constant_(m.bias, 0)
```

The output logits $z = [z_0, z_1, z_2]$ are mapped to a calibrated probability distribution using the Softmax function:
$$P(y = c \mid X) = \frac{e^{z_c}}{\sum_{j=0}^{2} e^{z_j}}$$
where $c \in \{0: \text{Normal}, 1: \text{Benign}, 2: \text{Malignant}\}$.

## 5.3 Mathematical Formulation of the Grad-CAM Engine
The explainability engine identifies the convolutional features that contribute most strongly to class $c$. It attaches forward and backward hooks to the final residual block (`model.resnet.layer4[-1]`):

```
       [Forward Pass]
Input Tensor ──► Conv Layers ──► Layer 4 Feature Maps (A^k) ──► FC Head ──► Score (y^c)
                                            │                                  │
                                            │ Hook captures A^k                │ Backprop
                                            ▼                                  ▼
                               [GAP of Gradients: α_k^c] ◄────────── ∂y^c / ∂A^k
                                            │
                                            ▼
                           Linear Combination: Σ (α_k^c · A^k)
                                            │
                                            ▼
                                     ReLU Activation
                                            │
                                            ▼
                           Raw Class Activation Map (CAM)
```

1. **Neuron Importance Weight Calculation:** Global average pooling is applied to the backward gradients across spatial dimensions (height $U=7$, width $V=7$):
   $$\alpha_k^c = \frac{1}{Z} \sum_{i=1}^{U} \sum_{j=1}^{V} \frac{\partial y^c}{\partial A_{i,j}^k}, \quad Z = U \times V = 49$$
2. **Feature Combination and Rectification:** The forward feature activations $A^k$ are weighted by $\alpha_k^c$ and passed through a ReLU activation to retain positive contributors:
   $$L_{\text{Grad-CAM}}^c = \text{ReLU}\left(\sum_{k=1}^{2048} \alpha_k^c A^k\right)$$
3. **Memory Management via Hook Deregistration:** To prevent memory leaks during sustained inference, hooks are deregistered in a `finally` block after each pass:
   ```python
   def remove_hooks(self):
       for handle in self.handles:
           handle.remove()
       self.handles.clear()
   ```

## 5.4 Thoracic Cavity Segmentation & JET Colormap Fusion
To prevent activation artifacts from appearing outside anatomical areas, the system applies an automated segmentation mask:

```python
# Thoracic background masking (backend/app/explainability/gradcam.py)
gray_img = cv2.cvtColor(img_np, cv2.COLOR_RGB2GRAY)
bg_mask = (gray_img < 25) # Isolate low-density air and background regions

# Standardize CAM to uint8 and apply JET colormap
cam_uint8 = np.uint8(255 * cam_resized)
heatmap_bgr = cv2.applyColorMap(cam_uint8, cv2.COLORMAP_JET)
heatmap_rgb = cv2.cvtColor(heatmap_bgr, cv2.COLOR_BGR2RGB)

# Blend composite overlay: 60% original image + 40% thermal heatmap
overlay_rgb = cv2.addWeighted(img_np, 0.6, heatmap_rgb, 0.4, 0)

# Restore true grayscale pixels across masked background
overlay_rgb[bg_mask] = img_np[bg_mask]
```

$$\text{Final Overlay}(x, y) = \begin{cases}
0.6 \cdot I(x, y) + 0.4 \cdot H_{\text{JET}}(x, y) & \text{if } I_{\text{gray}}(x, y) \ge 25 \\
I(x, y) & \text{if } I_{\text{gray}}(x, y) < 25
\end{cases}$$

## 5.5 Quantitative ROI Metric Extraction Engine
To provide actionable data alongside heatmaps, the system computes key Region of Interest (ROI) metrics:
* **Peak Activation Coordinate:**
  $$(y^*, x^*) = \arg\max_{(y, x)} S_{y, x}$$
* **High-Activation Area Percentage:**
  $$A_{\text{high}} = \left(\frac{1}{N_{\text{total}}} \sum_{x=1}^{224} \sum_{y=1}^{224} \mathbb{I}(S_{x, y} > 0.60)\right) \times 100\%$$
* **Peak Activation Intensity:**
  $$I_{\text{peak}} = \max_{(x, y)} (S_{x, y}) \times 100$$

These metrics are returned in the JSON payload:
```json
"roi_stats": {
  "peak_coordinate": {"x": 112, "y": 140},
  "high_activation_area_pct": 5.01,
  "peak_intensity": 98.6
}
```

# CHAPTER 8: CONCLUSION & FUTURE SCOPE

## 8.1 Conclusion
The **PulmoXAI** project successfully addresses the "Black Box" challenge of deep learning in thoracic oncology. By pairing a fine-tuned **ResNet-50** architecture with a custom, hook-managed **Grad-CAM** explainability engine, the system delivers both diagnostic classifications and verifiable visual explanations.

Key accomplishments of the project include:
1. **Explainable Diagnostic Workflow:** Generated thermal JET visual heatmaps that highlight suspicious pulmonary tissue while masking out non-anatomical background regions.
2. **Quantitative Biomarkers:** Extracted reproducible ROI metrics, including peak activation coordinates, high-activation area percentages, and peak gradient intensities.
3. **Clinical-Grade User Interface:** Developed an interactive web client featuring split-slider comparisons using CSS `clip-path`, bone window inversion, and printable clinical diagnostic reports.
4. **Stable Backend Architecture:** Delivered an asynchronous microservice using FastAPI and PyTorch with reliable hook cleanup, thread-safe database logging, and sub-second inference latency ($\approx 0.42\,\text{s}$).

---

## 8.2 Clinical Limitations
* **2D Cross-Sectional Analysis:** The current system analyzes independent 2D axial slices rather than reconstructing full 3D volumetric CT nodule volumes across multiple slices.
* **Dataset Scope:** While the model performs well on standard benchmark distributions, broader validation across multi-center clinical datasets is recommended to evaluate performance under varying scanner protocols and slice thicknesses.
* **Clinical Boundary:** The system serves as a decision-support aid and does not replace biopsy confirmation or the diagnostic judgment of a certified radiologist.

---

## 8.3 Future Enhancements
* **3D Volumetric Explainability:** Extend the Grad-CAM pipeline to 3D CNN backbones (e.g., 3D ResNet, 3D UNet) to calculate total nodule volume ($mm^3$) across contiguous CT slices.
* **Direct DICOM PACS Integration:** Implement native DICOM parsers (`pydicom`, `cornerstone.js`) with support for hospital PACS networks via DICOM C-STORE and C-FIND protocols.
* **Multi-Modal Diagnostic Integration:** Combine imaging data with patient clinical history, smoking pack-years, and genomic biomarkers using multi-modal transformer architectures.
* **Federated Learning:** Support privacy-preserving federated training across multiple hospital networks without requiring centralized pooling of sensitive patient scans.
